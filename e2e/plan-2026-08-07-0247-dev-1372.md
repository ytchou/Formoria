# DEV-1372 E2E Authoring Plan

## Journey 1 — Synchronized Creative Expo explorer

- Actor: Anonymous desktop visitor planning an expo visit.
- Goal: Narrow the Formoria exhibitor subset by official zone, product category, and search, then open a permanent brand page without losing the event context on Back.
- Pre-conditions: The published `2026-taiwan-creative-expo` event and canonical linked K1/K2/K3/S roster are available.
- Steps: Open the event; select a map zone; select a category; compare map/result counts; load `?zone=K2&category=crafts`; search by official name, Romanized name, and booth; clear all filters; open a brand and return.
- Expected: Map and list stay synchronized; compatible filters compose; URL state hydrates; each search identifies the right booth/zone; reset restores all brands and map state; brand navigation succeeds and Back restores explorer state.
- Risk if broken: Visitors are sent to the wrong hall or cannot recover/share their planning state.
- DB/auth state: Anonymous, canonical production-like event roster; no mutation or ambient-row assumption beyond the DEV-1370 manifest contract.
- Target project: `deep` (`@smoke`, desktop Chromium).
- Destination: `e2e/tests/event-detail.spec.ts`.

## Journey 2 — Degraded, localized, and preserved event contract

- Actor: Anonymous visitor in English or Traditional Chinese, including a visitor whose map image cannot load.
- Goal: Keep using the exhibitor list and trust the event's source/SEO information.
- Pre-conditions: Published Creative Expo event; local map-image request can be failed at the browser network boundary.
- Steps: Observe both locales; verify source attribution and official links; fail the map image request; use results; inspect server response and existing metadata/JSON-LD.
- Expected: Localized explorer copy is visible; source attribution remains; list interaction works without the image; brand links exist in server HTML; canonical, ISR response, and Event JSON-LD remain intact.
- Risk if broken: A media failure blocks the primary utility, or the event loses discoverability/trust signals.
- DB/auth state: Anonymous, read-only canonical roster.
- Target project: `deep` (desktop Chromium).
- Destination: `e2e/tests/event-detail.spec.ts`.

## Journey 3 — Mobile explorer switching

- Actor: Anonymous visitor using a phone at the venue.
- Goal: Switch between `[地圖]` and `[品牌清單]`, filter/search, and open a brand without horizontal page scrolling.
- Pre-conditions: Published Creative Expo event and linked roster.
- Steps: Open at Pixel 5 viewport; switch panels; choose a zone and category; search; switch away and back; open a result.
- Expected: Controls remain usable, filter state survives panel switches, result/map counts agree, and the document does not overflow horizontally.
- Risk if broken: The on-site mobile planning flow becomes unusable.
- DB/auth state: Anonymous, read-only canonical roster.
- Target project: `mobile`.
- Destination: `e2e/tests/mobile.spec.ts`.

## Deferred states

- Canonical empty roster and roster-read failure cannot be induced without mutating shared event data or mocking the service/component. Keep both as P2 backlog until a safe fixture or dedicated preview mode exists.
